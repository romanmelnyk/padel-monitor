# Падел-монітор (twojtenis.pl + tenis4u.pl)

Кожні 30 хвилин і щоночі рівно о 00:01 перевіряє розклад падел-кортів у клубах із `config.json`:
- **Fame Sport Club** (tenis4u.pl): лише «padel hala» (у залі), бронювання на 30 днів наперед. Корт надворі «padel zewnętrzny» (id 1197) виключено через `exclude_station_ids`;
- **Padel House** (tenis4u.pl): Padel 1–4, бронювання лише з початку години, на 14 днів наперед;
- **Błonia Sport** (twojtenis.pl): Padel 1–4, бронювання на 7 днів наперед. Щоб вимкнути цей клуб, поставте `"enabled": false`.

Записує, які слоти звільнились або були заброньовані, і надсилає в Telegram повідомлення, коли у ваш час (Пн–Пт 18:00–23:00, суцільно від 1.5 години) з'являється вільний корт. Бронюєте ви самі за посиланням.

Дані беруться з тих самих запитів, які роблять сайти, без логіну (12 запитів за запуск).

## Файли

| Файл | Що робить |
|---|---|
| `config.json` | клуб, тип корту, фільтр сповіщень (`alerts`) |
| `collector.py` | збір даних, журнал змін, Telegram |
| `analyze.py` | будує звіт `reports/report.md` |
| `.github/workflows/monitor.yml` | розклад запуску в GitHub Actions |
| `data/events.csv` | журнал подій (створюється автоматично) |
| `data/runs.csv` | журнал запусків |
| `data/state.json` | поточний стан вільних слотів (зберігається в кеші Actions, не в репозиторії) |

## Налаштування (одноразово, ~15 хв)

### 1. Telegram-бот
1. У Telegram відкрийте **@BotFather** → `/newbot` → придумайте ім'я. Збережіть **токен**, який він видасть.
2. Знайдіть свого нового бота і надішліть йому будь-яке повідомлення (наприклад, `/start`).
3. Відкрийте в браузері `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, знайдіть `"chat":{"id":123456789` — це ваш **chat id**.

### 2. Репозиторій на GitHub
1. Створіть акаунт на github.com (якщо немає) → **New repository**, наприклад `padel-monitor`.
   - **Public** — хвилини Actions безкоштовні без ліміту. У репозиторії будуть лише публічні дані про зайнятість кортів; токен зберігається в секретах і не видний.
   - **Private** не підходить: монітор працює майже цілодобово, а безкоштовний ліміт для приватних репозиторіїв — 2000 хв/міс.
2. **Add file → Upload files** → перетягніть `config.json`, `collector.py`, `analyze.py`, `README.md`, `.gitignore` → Commit.
3. **Add file → Create new file** → у полі імені введіть `.github/workflows/monitor.yml` → вставте вміст файлу → Commit.

### 3. Секрети
**Settings → Secrets and variables → Actions → New repository secret**:
- `TELEGRAM_BOT_TOKEN` = токен від BotFather
- `TELEGRAM_CHAT_ID` = ваш chat id

### 4. Запуск
**Actions** → (якщо треба, увімкнути workflows) → **padel-monitor** → **Run workflow**.
За хвилину в Telegram має прийти «✅ Падел-монітор запущено…» зі списком вільних зараз слотів. Далі все працює за розкладом.

## Автобронювання (Fame, Padel House, Błonia)

`booker.py`, налаштування в `config.json` → `booking`:
- у будні 18:00–23:00 бот бронює **один корт на день**: найраніший вільний блок, 2 год (якщо блок коротший, то 1.5 год; у Padel House лише цілі години);
- **до гри ≥ 30 год** (`auto_min_lead_hours`): бронює сам і надсилає повідомлення з кнопкою «❌ Скасувати бронь». Безкоштовно скасувати можна до 24 год перед грою;
- **менше 30 год**: надсилає пропозицію з кнопками «✅ Забронювати» / «Пропустити»;
- день, де у вас уже є бронь у tenis4u (зроблена будь-ким), бот пропускає. Скасований або пропущений день більше не пропонує;
- не більше `max_active_auto` (3) автоброней одночасно, далі тільки пропозиції;
- оплата в клубі (тариф з оплатою CASH).

Потрібні секрети `TENIS4U_LOGIN` і `TENIS4U_PASSWORD` (Fame, Padel House), `TWOJTENIS_LOGIN` і `TWOJTENIS_PASSWORD` (Błonia) у Settings → Secrets and variables → Actions.
twojtenis не дозволяє входити паролем напряму, тож бот входить через невидимий браузер (`tt_login.py`, Playwright). Якщо сайт покаже перевірку «я не робот», бронювання в Błonia не вдасться і прийде повідомлення з причиною. Час, до якого можна скасувати бронь у Błonia, бот бере з відповіді клубу. Перевірити вхід без бронювання: Actions → **booking-check** → Run workflow.
Кнопки працюють, поки йде запуск монітора (майже завжди); відповідь на натискання приходить за кілька секунд.
**Календар iCloud** (`icloud_cal.py`, CalDAV): після кожної броні бот додає подію (з нагадуванням за 2 год) у календар із секрету `ICLOUD_CALENDAR`, а при скасуванні кнопкою в Telegram прибирає її. Секрети: `ICLOUD_USER` (Apple ID), `ICLOUD_APP_PASSWORD` (пароль для застосунків з appleid.apple.com), `ICLOUD_CALENDAR` (точна назва календаря). Без цих секретів бот надсилає файл `.ics` у Telegram.
Actions → **booking-test**: `ics` додає в календар уже наявну бронь, `book` робить справжню бронь вказаного слоту.
Вимкнути: `"enabled": false` у `booking`.

## Звіт

Відкрийте `reports/report.md` у репозиторії (оновлюється щоразу). Він показує:
- скільки годин корту звільняється (скасування) і на який час гри;
- о котрій годині доби та за скільки до гри з'являються скасування;
- як швидко звільнені слоти забирають інші;
- скільки вільно при відкритті нового дня і як швидко його розбирають;
- що лишається непроданим.

Корисні висновки з'являться приблизно через 1–2 тижні збору.

## Клуби (`config.json` → `sources`)
- Вимкнути клуб: `"enabled": false`.
- **Інший клуб на tenis4u.pl:** відкрийте його в app.tenis4u.pl. Число в адресі `app.tenis4u.pl/court/<число>` вставте в `court_id` і `booking_url`, а також змініть `short` і `name`.
- **Інший клуб на twojtenis.pl:** скопіюйте ідентифікатор з адреси `app.twojtenis.pl/#/clubs/<id>` у `club_id` і `booking_url`.
- `short` має бути унікальним: з нього починається назва корту в даних, наприклад «Fame · Padel hala».

## Налаштування фільтра (`config.json` → `alerts`)
- `weekdays` — 0 = Пн … 6 = Нд
- `from` / `to` — проміжок часу гри
- `min_duration_minutes` — мінімальна тривалість вільного блоку
- `on_window_open` — `true` (увімкнено): повідомлення й тоді, коли відкривається новий день для бронювання

## Обмеження
- Опівночі: о 00:01 (за Варшавою) завжди є окрема перевірка, а запуск ніколи не завершується з 23:45 до 00:20. Про нові дні приходить окреме повідомлення «🆕 Відкрилось бронювання» (`on_window_open: true`). О котрій реально відкриваються нові дні в кожному клубі, видно у звіті, у розділі «Відкриття нового дня».
- Як це працює: один запуск в Actions триває ~5 год і перевіряє клуби кожні 30 хв (`POLL_SECONDS` у `monitor.yml`). Наприкінці він сам ставить у чергу наступний запуск, тож перерв немає. Журнали й звіт комітяться після кожної перевірки.
- Зміни в `config.json` і коді підхоплюються під час роботи протягом ~30 хв. Зміни в самому `monitor.yml` застосуються лише з наступного запуску (до 5.5 год). Щоб застосувати одразу, скасуйте поточний запуск у вкладці Actions і натисніть Run workflow.
- Слот, який звільнився і був заброньований швидше ніж за 30 хв, не потрапить ні в журнал, ні в сповіщення.
- Частоту окремого клубу можна обмежити в `config.json`: `min_interval_seconds` (звичайно) і `hot_interval_seconds` (23:57–00:10). Після ~18 частих запитів поспіль tenis4u починає віддавати серверу GitHub «порожні» дані (наче на місяць усе зайнято) і не відновлюється годинами. Таку відповідь монітор вважає збоєм: не змінює стан клубу, робить паузу від 10 до 60 хв і записує відповідь сервера в `data/diag.jsonl`. Якщо збій триває 30 хв, приходить попередження в Telegram.
- API неофіційні: якщо сайт їх змінить, збирач перестане працювати для цього клубу (інші клуби працюватимуть далі). Після ~30 хв невдалих перевірок поспіль прийде попередження в Telegram.
- tenis4u.pl приймає лише запити із заголовком версії свого вебзастосунку (`client_header`, зараз `tenis4u-web-frontoffice/3.6.3`). Коли вони оновлять застосунок, сервер відповідатиме 403 `WYMAGANA_AKTUALIZACJA`. Тоді потрібно оновити номер версії в `config.json`.
- Скрипт для tenis4u представляється їхнім вебзастосунком, а це формально може суперечити правилам сервісу. Запитів небагато (по одному на клуб раз на 30 хв і о 00:01), але рішення про використання за вами.
